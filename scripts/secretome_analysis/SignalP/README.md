# SignalP 6 batch analysis of fungal protein FASTA files

This repository contains a Bash workflow to run **SignalP 6** on multiple protein FASTA files in WSL/Ubuntu and extract the complete original protein sequences predicted as signal-peptide-positive (`SP`).

**This repository runs SignalP only. It does not run DeepTMHMM.** DeepTMHMM can be run later as a separate analysis on the `signal_positive.faa` files.

## 1. What the workflow does

For every supported FASTA file directly inside the input directory, the script:

1. Runs SignalP 6 using the eukaryote model, fast mode, and batch size 32.
2. Reads `prediction_results.txt`.
3. Selects entries whose prediction column is `SP`.
4. Retrieves the corresponding **full-length original protein sequences** from the input FASTA.
5. Writes those sequences to `signal_positive.faa`.
6. Keeps the SignalP output files and a log for that isolate.
7. Writes a completion marker so a later restart can skip completed files.
8. Preserves previous outputs as timestamped backups before replacing them.

The script processes files at the top level only. It does not recursively enter subfolders.

## 2. Input and output paths used in this project

The paths below are the paths currently configured in the supplied script.

| Purpose | Windows path | WSL path |
|---|---|---|
| Input protein FASTA files | `F:\fusarium WGS\ALL PROTEINS FOR FUNCTIONAL ANALSYSI` | `/mnt/f/fusarium WGS/ALL PROTEINS FOR FUNCTIONAL ANALSYSI` |
| Output root | `F:\fusarium WGS\secretome analysis\functional_analysis` | `/mnt/f/fusarium WGS/secretome analysis/functional_analysis` |

Only these filename extensions are included: `.faa`, `.fasta`, `.fa`, `.FAA`, `.FASTA`, `.FA`.

**Subfolders are excluded.** For example, files inside `genomes no analysis` and `pending poa` are not searched or processed because the script uses shell globs against the input directory itself, not a recursive file search.

If your folders are in different locations, edit `BASE` and `OUT` near the top of `01_signalp_functional_analysis.sh`.

## 3. Output structure

Each input file gets its own output directory based on its filename without the extension.

Example:

```text
secretome analysis/
└── functional_analysis/
    ├── Fbooth_CBS110251/
    │   ├── signalp/
    │   │   ├── prediction_results.txt
    │   │   ├── output.json
    │   │   ├── output.gff3
    │   │   └── ... other SignalP output files
    │   ├── signal_positive.faa
    │   ├── signalp.log
    │   └── signalp.done
    └── Fbooth_CBS119170/
        └── ...
```

Files of interest:

- `signal_positive.faa` — full-length original protein sequences for entries predicted as `SP`. This file can legitimately be empty if SignalP predicts no signal peptides for an isolate.
- `signalp/prediction_results.txt` — tabular SignalP predictions, including the prediction class.
- `signalp/` — other files generated by SignalP 6.
- `signalp.log` — standard output and error from the successful SignalP run.
- `signalp.done` — completion marker and input-file size/modification-time fingerprint.
- `signalp_failed_TIMESTAMP/` and `signalp_failed_TIMESTAMP.log` — retained output and log from a failed attempt.
- `signalp_backup_TIMESTAMP/` and related backup files — prior outputs retained when a new successful result replaces them.

## 4. Requirements

The workflow was prepared for this environment:

- Windows with WSL2 and Ubuntu
- Conda environment named `secretome`
- Python 3.10
- SignalP 6 package installed and importable as `signalp`
- Biopython available as `Bio`
- PyTorch installed in the environment and compatible with the SignalP package

The tested environment described by the project owner:

- Python 3.10.22
- PyTorch 1.13.1+cu117
- WSL did not expose CUDA; SignalP therefore ran on CPU.
- SignalP package directory: `/mnt/d/signalp-6-package`
- SignalP model weights: `/mnt/d/signalp-6-package/signalp/model_weights/distilled_model_signalp6.pt`

The SignalP software and model weights are not included in this repository. Obtain them from the official SignalP distribution under its applicable license. Do not upload licensed model weights or FASTA datasets to a public Git repository unless you have permission.

### Check the environment

```bash
conda activate secretome
python --version
python -c "import torch; print('PyTorch:', torch.__version__)"
python -c "import Bio; print('Biopython:', Bio.__version__)"
python -m signalp.predict --help
```

The last command should display SignalP command-line help. If it fails, configure/install SignalP and its licensed model weights before running the batch script.

## 5. Install / prepare

If the `secretome` environment already exists and SignalP works, do not reinstall or downgrade PyTorch just to run this script.

Biopython is required for extracting full-length sequences:

```bash
conda activate secretome
python -c "import Bio"
```

If Biopython is missing:

```bash
pip install biopython==1.79
```

The SignalP package has its own software and model requirements. Follow the installation instructions supplied with your licensed SignalP 6 distribution. This repository does not replace those instructions.

## 6. Run the workflow

Copy `01_signalp_functional_analysis.sh` into your WSL home directory, or clone this repository and change into the cloned directory.

Make it executable:

```bash
chmod +x 01_signalp_functional_analysis.sh
```

Run:

```bash
./01_signalp_functional_analysis.sh
```

Or, if it is in your home directory:

```bash
chmod +x ~/01_signalp_functional_analysis.sh
~/01_signalp_functional_analysis.sh
```

The script activates the Conda environment named `secretome` itself.

## 7. Resume after interruption

You can stop the running script with `Ctrl+C`. Start it again using the same command.

- A file is skipped only if the completion marker, SignalP prediction report, extracted FASTA, and input size/modification-time fingerprint all match.
- An incomplete run is attempted again.
- Failed temporary outputs and logs are retained with timestamped names.
- Existing completed output is not deleted; a previous result is moved to a timestamped backup only after a new run and sequence extraction succeed.

Do not run two copies of this batch script simultaneously against the same output directory.

## 8. Check how many files will be processed

This command counts supported FASTA extensions in the input directory itself, without entering subfolders:

```bash
find "/mnt/f/fusarium WGS/ALL PROTEINS FOR FUNCTIONAL ANALSYSI" \
  -maxdepth 1 -type f \
  \( -iname '*.faa' -o -iname '*.fasta' -o -iname '*.fa' \) \
  | wc -l
```

The script reports its own file count at startup. The count can differ from an earlier count if the earlier command counted only lowercase extensions or if files were added/removed.

## 9. Monitor a running isolate

In a second WSL terminal, for example:

```bash
tail -f "/mnt/f/fusarium WGS/secretome analysis/functional_analysis/Fbooth_CBS110251/signalp.log"
```

Stop `tail` with `Ctrl+C` in the monitoring terminal only. Do not interrupt the terminal running SignalP.

## 10. Important scientific interpretation

The script extracts records whose SignalP prediction class is exactly `SP`. It preserves the original full-length protein sequence, including the predicted signal peptide region.

This is a SignalP-positive candidate set. It is not yet a final secretome set. Further filtering may be performed in a separate downstream workflow, for example with DeepTMHMM and other biological criteria. DeepTMHMM is deliberately not included here.

## 11. Troubleshooting

### `No module named signalp`

Activate the correct Conda environment and verify SignalP installation:

```bash
conda activate secretome
python -m signalp.predict --help
```

### `No module named Bio`

Install Biopython in the active environment:

```bash
conda activate secretome
pip install biopython==1.79
```

### `Input folder not found`

Check the `BASE` path in the script. WSL mounts Windows drives under `/mnt/<drive-letter>/`.

### `Duplicate output name`

Two input files have the same basename but different extensions. Rename one file or adjust the output naming strategy before running.

### A run is interrupted

Restart the same script. Do not manually delete completed result folders. Incomplete temporary directories are retained for inspection.
